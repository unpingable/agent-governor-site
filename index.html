Agent Governor

A control and evidence layer for tool-using AI agents. Claims require evidence. Decisions produce receipts. Language is a proposal, not an authority.

Core invariant (NLAI)

Language is a proposal, not an authority.

The model can claim anything. It cannot write anything until evidence exists. Evidence must come from trusted collectors — test runners, linters, filesystem probes, git diffs — not from the agent itself.

Why

The problem

AI coding tools reduce effort locally but increase verification burden globally. An LLM writes 400 lines; a human reviews them against 300 pages of context. The human becomes a compiler for machine output.

Existing fixes — better prompts, style guides, "human in the loop" — are all advisory. They rely on the model cooperating with constraints it has no mechanism to enforce. That is not governance. That is hope.

Agent Governor is the structural intervention. It does not make models better. It makes their operations inspectable and their boundaries enforceable.

Scope

What Agent Governor is not

  • Not a model. It does not generate text.
  • Not an agent framework. It does not own a runtime.
  • Not alignment research. It does not make models good.
  • Not content moderation. It operates at the tool boundary, not the text boundary.
  • Not a confidence score. Confidence without evidence is theater.
  • Not an AI firewall or MCP gateway.

Your agent's built-in guardrails are the provider's opinion about what's safe. Governor is your opinion about what's allowed.

How

Four structural moves

Gate, not memory

Write gate

No file mutation without a verified proposal. Not an advisory log. A pre-commit hook with cryptographic receipts.

Typed claims, not prose

Structured claims

Agents submit typed claims like Claim(type=TESTS_PASS, command=["pytest"]). The governor runs the command and produces a receipt.

Evidence budgets, not output caps

Provenance tracking

Tracks where claims came from, how well-supported they are, and when evidence expired. Ungrounded claims don't get committed.

Receipts, not trust

Hash-chained receipts

SHA-256, content-addressed, tamper-evident. Same inputs produce the same receipt ID. Cannot be fabricated, backdated, or selectively omitted.

Architecture

Single authority pipeline

The governor daemon is the sole authority. Every client — desktop, web, terminal, IDE — is non-authoritative. Receipts are the common currency.

               agent_governor  (authority / kernel)
               governor serve  (daemon, JSON-RPC 2.0)

          +------------+------------+-----------+
          |            |            |           |
       guvnah    governor_webui  maude   vscode-governor

All clients render decisions. None of them make decisions. The daemon decides. The receipt proves it.

Adoption

Incremental adoption

You don't have to go from zero to full governance overnight.

  1. Receipts only — Observe. Collect provenance, no enforcement.
  2. Policy evaluation — Advisory. Surface what would be blocked.
  3. Enforcement — Scope, lanes, policy. Hard stops.
  4. Full governance — Claims, integrity checks, composition governance.
FAQ

Questions

Why not just use tool permissions?

Tool permissions are binary: allow or deny. Governor tracks provenance, evidence quality, and claim lifecycle across sequences of tool calls. A read followed by a write is different from a write alone. Permissions can't express that.

Why not rely on the model provider's guardrails?

Provider guardrails reflect the provider's risk model, not yours. They change without notice. They optimize for the provider's liability surface. Governor is the operator's policy, enforced locally, with receipts the operator controls.

What do receipts buy me?

Reconstructability. Every decision is a receipt: what was proposed, what evidence existed, what policy applied, what the verdict was. If something goes wrong, the chain tells you exactly where governance held and where it didn't.

Is this alignment research?

No. Agent Governor does not make models better, safer, or more truthful. It makes their operations inspectable and their boundaries enforceable. Outcomes are stochastic. Constraints and accountability are not.

What's the status?

Alpha. Solo development. 14,600+ tests across 60+ modules. Not yet packaged for distribution. The thesis is stable; the packaging is not.
